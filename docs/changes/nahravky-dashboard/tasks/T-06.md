## Převzatý výsledek

- Workflow ověří tag, potvrzenou zálohu a konfiguraci před klíčem, spustí společné gates a vytvoří review artifact.
- Validátor kontroluje čtyři balíčky, blockmapy, metadata a vloženou podepsanou/notarizovanou `.app` pro arm64/x86_64.
- SCP používá pinned known_hosts; remote helper ověří SHA-256, odmítne konfliktní obsah stejné verze a povýší feed poslední.
- Navazující veřejná HTTPS kontrola porovná verzi/metadata a HEAD velikost osmi artefaktů.
- Updater zobrazuje dostupnou verzi/průběh a zachovává bariéry nahrávání, ukládání a LuTracku.
- Stav zůstává 🟡/🧪: klíč nebyl použit, nová verze nebyla podepsána, publikována ani živě nainstalována.

## Sabotáže

Jde o historický důkaz, ne o pokyn měnit přijatý kód.

### MUSÍ ZČERVENAT

1. Hash mismatch nebo chybějící veřejný artefakt musí shodit release/publication test; doslovné výstupy jsou v `T6-public-sabotaz.log` a release evidenci.

### MUSÍ ZŮSTAT ZELENÉ

1. Mocked files-first/feed-last cesta, validace embedded aplikace a updater bariéry zůstávají zelené bez klíče, tagu nebo produkčního SCP.

## Postup při případné reprodukci — dodrž pořadí

1. Ověř převzaté commity a `T6-VYDANI.md`; nepoužívej secrets ani síť.
2. Spusť typecheck `npm run typecheck` a zachovej doslovný výstup i exit kód.
3. Spusť testy `npm run gates` a zachovej doslovný výstup i exit kód.
4. Porovnej archivovanou sabotáž s obnoveným kódem; nevytvářej tag ani live release.
5. Spusť `git --no-pager status --porcelain` jako jediný read-only Git self-check.
