## Tělo zadání

### Trvalá akce v hlavním procesu

Přidej revizi položky do bezpečné projekce (například deterministický otisk jejího aktuálního trvalého obsahu) a metodu store pro převzetí jedné konkrétní nahrávky. Identifikátor i revize se validují. Operace musí být uvnitř existující serializace a odmítne neaktuální snímek, neexistující položku, již odeslanou či právě odesílanou položku a neplatný/null otisk nového vlastníka.

Hlavní proces smí získat nový otisk pouze z aktuální platné relace správného issuer/resource/scope. Renderer otisk neposílá. Při čekání na potvrzení i serializaci může proběhnout logout či změna účtu: kontrola při skutečném provedení a generační ochrana nesmí zapsat jiný účet než uživatel potvrdil.

Převzetí vyčistí blokaci a serverová ID/session patřící starému vlastníkovi. Identita původní lokální nahrávky a soubory zůstávají stejné. Převzetí samo nespouští upload; následná volba odeslání patří T5. Obnova nadále zachovává neznámého vlastníka jako neznámého.

Nový IPC kanál použije `handleValidated` a povolí jen očekávané lokální okno. Potvrzení musí být skutečně viditelné, zrušení nesmí nic zapsat. Výsledek je bezpečná projekce, žádná cesta či otisk vlastníka v rendereru.

### Viditelná akce v Nastavení

Přidej samostatnou záložku Nahrávky s malou komponentou. Stávající Záznamy a jejich retence/localStorage klíč zůstávají funkční. V T2 stačí položky fronty (soubory mimo frontu až T3). Datum, délka, velikost, důvod blokace a per-item „Převzít pod svůj účet“. U cizího účtu jasně říct, že přebíráš nahrávku vzniklou pod jiným účtem.

Bez platného přihlášení akce není dostupná a UI vysvětluje proč. Během akce zabránit dvojkliku; při chybě nabídnout čerstvé načtení. Prázdný seznam a chyba načtení jsou různé stavy. Síť na server se při otevírání této záložky nevolá.

Použij existující CSS tokeny, žádný nový `:root` ani knihovnu. Nech malé okno, pokud se do něj čitelně vejde; případnou změnu rozměrů zapiš jako konkrétní rozhodnutí. Neimplementuj ještě T3/T4.

## Akceptace a sabotáže

- Platné potvrzené převzetí jedné položky přetrvá po znovuotevření store; jiná položka se nezmění.
- Zrušení, null/expired session, cizí IPC odesílatel, změna účtu během dialogu a stale revision nezpůsobí zápis.
- Staré serverové ID se po změně vlastníka nepoužije. Žádný serverový request během převzetí.
- UI test skutečně klikne na záložku/tlačítko a projde úspěchem, zrušením i chybou.
- Sabotáž odstranění validace vlastníka nebo revize musí shodit konkrétní regresní test. Poté obnov kód a ověř zelený legitimní případ.
- Koordinátor zopakuje cílené testy; worker uloží doslovné výpisy s exit kódem do `dukazy/nahravky-dashboard-2026-09-14/T2/` a spustí `npm run gates`.
